Chirograph

Typed HTTP clients generated from OpenAPI documents at build time. One MSBuild item, a Kiota or Refitter client, registered with IHttpClientFactory.
Get startedView on GitHub

A chirograph was a medieval contract written twice on one sheet and cut apart, so each half proved the other. Here the OpenAPI document and the generated client are the two halves: Chirograph keeps them together by generating the client from the document on every build that needs it.

Declare a client with one item. Where its document comes from is inferred from the Include:

  • A file
  • A server project
  • A URL

Then register it, and give it a base address in Clients:RocketsClient:BaseAddress:

Note

Chirograph has no release on nuget.org yet. Getting started shows how to pack it from a clone until the first beta ships.

Two generators you already use

Kiota, or Refit through Refitter. Chirograph generates no code of its own, so it keeps each generator’s fidelity and follows their releases by changing a version.

Three sources

A file in the project, a server project in the same build, or a URL with a document cache you can commit.

Quiet builds

Tools come from the packages folder, output stays in obj, generation is incremental, and the generators’ telemetry is off.

Registered

Every client gets an Add<ClientName>() extension that registers it with IHttpClientFactory and returns the IHttpClientBuilder.
